# Native Cargo continuation

This continues [PR #33](https://github.com/glopyglerky/lustr/pull/33) under the
[exclusive coverage contract](exclusive-coverage-contract.md). It repairs
Lust-owned integration uncovered by independent retained-result qualification.
It is not a complete Rust compiler, a new complementary owner, or a release.

## Cargo supplies a plan; Lust compiles the source

The new product service uses the declared, byte-verified Cargo's planning-only
unit graph. It reads the exact selected units, per-unit features and dependency
edges. Cargo can issue the packaged native entry's information queries; it
cannot compile a trial program to choose an owner. The resulting source units
enter Lust's existing dependency worklist and native compiler.

The planner binds package, target kind, target name and canonical source before
body or host-script work. An explicit selector remains distinct from a name
inferred from a source filename. Ambiguity, a foreign source and an unavailable
target are errors. An inferred library cannot bypass the existing refusal to
claim an unimplemented Rust library artifact.

Ordinary manifest-selected requests no longer repeat a separate public Cargo
metadata pass before the retained native resolver. Explicit package binding and
missing-source diagnostics retain their necessary entry behavior. The normal
graph cache checks changes to manifests, lock/configuration inputs and target
discovery; it does not publish metadata under the identity preceding a newly
created lockfile.

A fresh explicit `--package` request exposed a separate binder error: Cargo's
`pkgid` requires a lockfile, while metadata with `--no-deps` had not created one.
Only explicit-package binding now asks Cargo for normal metadata resolution
before `pkgid`. This is planning, with no source compilation. Ordinary
manifest-selected requests still avoid that public pass. The explicit-package
path retains additional planning cost and is not covered by the ordinary warm
zero-Cargo claim.

The unit-plan cache binds those graph facts, request mode/profile and verified
tool identities. Unchanged tool file identities reuse their earlier byte
verification. A warm hit does not start Cargo or an external file-hash process.
The hosted process control observes a real daemon and its children, checks the
same daemon identity across requests, and compares generated program results
with the independent Rust oracle. A query spy rejects compilation requests even
when they contain a print option. A local cold-only run is identified separately.

This service currently admits its represented Linux host, source-unit,
edition/profile and configuration contexts. Registry/git source integration,
procedural macros, host build dependencies and unrepresented configuration
remain explicit gaps. These limits do not redefine what Lust owns.

## Native host scripts retain their actual dependencies

The selected Cargo plan describes each original host script. The native
pipeline prepares, checks and emits that script, then executes its artifact.
No Cargo check or Rust compiler supplies the script's implementation. A failure
ends the request; no second host attempt repairs its result.

Compilation and runtime output have separate reuse records. Compilation reads
come from the actual native source, expansion-environment and negative module
lookup observations. Unrelated `LUST_*` runtime variables and per-request trace
paths do not force an unchanged script to compile again. Cargo configuration
identity changes can still require replanning and a new host record. Adding a
competing module candidate invalidates a recorded
absence and requires native checking again.

Runtime records bind the declared file/environment inputs and generated output.
Known explicit inputs get narrow observations. The default package contract
and first execution require broader observations. A run that changes an input
or names an input not observed before execution can return its actual successful
output, but cannot certify that output for reuse. The next logical request may
execute it once using the newly known input paths. A timestamp alone cannot
bind old output to newer input bytes.

The consumer owns a lease on each generated output directory through checking
and emission, including deferred includes and expansion reads. Duplicate uses
of the same planned script share that lease and output rather than reacquiring
the lock or executing the script again. Record publication is atomic; failed
source, execution or publication does not become a successful old generation.

The runtime environment preserves caller entries and overlays Cargo's generated
fields. Feature names, empty feature lists, compile-only crate/bin names and
positive numeric job counts have explicit controls. The independent environment
comparison still records unsupported backend-reliability fields. Native f16/f128
arithmetic or math support is not asserted merely to copy Rust's capability
flags.

Target/configuration repairs include the demonstrated x87 branch mismatch and
represented Linux object/thread/atomic and profile facts. Reporting the
requested UB-check configuration does not implement missing UB instrumentation.
Reporting Rust's target-default relocation metadata does not establish native
PIC/PIE emission. Those implementation obligations remain open.

Removing the old Rust preparation also exposed permissive cfg directive
consumers. Actual before controls demonstrated malformed and builtin cfg false
acceptance, plus an escaped-value result mismatch. Native directive admission
now checks represented token forms before using those consumers. Unrepresented
escapes, builtin overrides and other unsupported forms remain explicit native
integration work; they cannot silently select a different branch or compiler.
This does not claim complete Rust cfg lint or declaration checking.

## Remaining compiler boundary

These changes advance Lust coverage, composition, retained dependencies and
qualification in checklist items 1, 3, 4 and 6. No new competing Rust frontend
or compiler dependency closure is imported. The full Rust source stays in
blueFe, and the protected Lust and Rust pins remain unchanged. The TinyCC
signing repair has its own source declaration.

There is no new matched compiler-speed result here. Avoiding repeated planning,
tool hashing and host compilation removes identifiable costs, but process
counts do not bound all conversion, lookup, checking or emission costs. First
planning, script-input observation, locking and output validation still cost
time. The [total-time policy](practical-performance.md) governs the eventual
measurement; historical or synthetic performance records cannot qualify this
source.

The next compiler boundary remains [genuine consumer metadata](shared-consumer-metadata.md):
accepted definitions, declaration/privacy/lint completion and the actual emitted
instance graph must reach the genuine encoder without whole-consumer Rust
analysis. General complementary coverage, all required Rust artifacts and full
language/profile/target qualification remain unfinished. The implementation
still uses `std` and Unix sockets.

The first release remains a correct, complete replacement that beats matched
stock rustc overall. The provisional subset budgets are optimization targets,
not extra release prerequisites. Matching stock Lust remains the continuing
goal after that release.

The subsequent [repository-wide follow-through](sole-goal-audit.md#construction-and-evaluator-follow-through)
binds compiler construction to reviewed source/target modes, removes unused
expanded-source packaging and retires the remaining whole-compiler measurement
routes. It also tightens independent test-result admission. Those changes
preserve this continuation's actual native work and failed evidence; they do
not complete the metadata caller, general complement, portability migration or
matched speed qualification.
